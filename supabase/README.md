# Database setup (Supabase)

All schema lives in `migrations/` (numbered, run in order, safe to re-run).
`APPLY_ALL.sql` is the same thing in one file — generated by `npm run db:bundle`, never edit it by hand.

## 1. Apply the schema

1. Supabase Dashboard → **SQL Editor** → **New query**.
2. Paste the whole of [`APPLY_ALL.sql`](APPLY_ALL.sql) → **Run**.
   - If the editor warns about tables without RLS, pick **Run** — migration 0006 enables RLS on every table in the same script.
3. Check it worked:

```sql
-- every public table should show rls = true
select relname as table, relrowsecurity as rls
from pg_class c join pg_namespace n on n.oid = c.relnamespace
where n.nspname = 'public' and c.relkind = 'r'
order by 1;
```

## 2. Auth settings (Dashboard → Authentication)

| Setting | Value | Why |
|---|---|---|
| Sign In / Providers → **Allow new users to sign up** | **Off** | Accounts are invite-only |
| Providers → **Email** | **On** | Phone login uses an internal email behind the scenes |
| Providers → Email → Minimum password length | **6**, no required characters | No password rules (owner's choice) |

> **Sign-up lock (0008):** the database rejects every new `auth.users` row that doesn't come from
> `create_app_user()`. Public sign-ups and the Dashboard's **Add user** button will fail with
> "Sign-ups are disabled" — that's intended. Always create users with the SQL below.

## 3. Create a user

Login is **phone + password**. Run in the SQL Editor (one line per person):

```sql
select public.create_app_user('9876543210', 'Uday Yadav');
```

- Default password: set by the owner (not written here). The user must change it on first login.
- Accepts `9876543210`, `+91 98765 43210` or `09876543210`.
- If the editor warns about `auth.users`, choose **Run without RLS** — never "Run and enable RLS" on `auth.users`.
- Each new user automatically gets their own copy of functions, venues, sub-venues, sessions and tiers.

## 4. Forgot password

```sql
select public.reset_user_password('9876543210');
```

Sets it back to the default password and forces a change at next login.

## 5. Remove a user

Dashboard → Authentication → Users → delete. All of that user's data is deleted with it (`on delete cascade`).

## Tests

`npm test` runs these migrations inside PGlite (real Postgres, in-process) against a small Supabase shim
([`tests/supabase-shim.sql`](tests/supabase-shim.sql)) and checks per-user isolation, constraints, quote
freezing, append-only history, rate limiting and the account helpers. See [`tests/db.test.ts`](tests/db.test.ts).
